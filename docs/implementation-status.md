# Initial delivery status

## Implemented

- Portable PHP/SQLite application and a shared responsive interface for all seven apps.
- Owner setup/login, sessions, CSRF checks, encrypted provider credentials, stale-write rejection, unique wiki names and text revisions.
- Functional local tasks, contacts, agenda, rich-text documents, Markdown wiki and multi-sheet workbooks.
- Home-row application commands and remapping, standard keyboard focus, light/dark/system themes, three accent palettes and compact density.
- JSON backup/restore and item import/export; CSV workbooks, basic vCards, ICS, EML, text, Markdown and safe HTML. Original binary mail source is stored as base64; original ICS sources can be downloaded. See the current [import and export guide](import-export.md) for formats and size limits.
- Multipart mail reading extracts plain text or converts HTML to text, decodes transfer encodings/charsets and excludes attachments. Existing cached multipart notices are replaced on read using the retained original, without changing provider state or record revisions. File attachments now have metadata lists, image/PDF previews, individual downloads, ZIP Save all, draft uploads/removal, forwarding and multipart sending. IMAP BODYSTRUCTURE and Gmail payload metadata allow on-demand part downloads; bytes are cached separately in SQLite and included in backup/restore. Complete MIME support remains deferred.
- Active-use Gmail/Google Calendar, IMAP/SMTP and CalDAV connector code; read/archive mail actions; explicit sends with a persisted uncertain state on failure. No cron jobs, automatic sends or background workers.
- Guided and manual account setup with shared validation, drafts preserved across paths/provider changes, masked review, connection checks that do not save or download, installation-level Google settings, copyable callback, and Google sign-in with optional Calendar before account creation. Gmail identity and requested permissions are verified before saving through OAuth. Gmail app-password setup supplies IMAP/SMTP settings without OAuth configuration, normalizes grouped passwords, and detects localized All Mail and Trash through server flags. Connection checks inspect Inbox, archive/MOVE support, Trash, and SMTP login without sending or moving mail. Live Gmail app-password and folder-action acceptance remains open.
- Windows batch launch/stop scripts and a release bundle containing the official PHP executable/DLLs, configuration and a CA bundle. Linux shared-hosting ZIP contains the application but no Windows runtime binaries.

## Acceptance still required

- Actual hosting.com account: PHP extensions, public document root, SQLite locks, outbound TLS ports and shared-host execution limits.
- Real Gmail OAuth authorization/refresh, provider messages, calendar collections, SMTP acceptance, IMAP MOVE behavior and mailbox-specific folder names. Local fixtures are not provider acceptance.
- Gmail IMAP Trash correction: defaults prefer server-designated system folders over same-named custom labels. Moves refresh the source view and verify the destination using `X-GM-MSGID`, including existing destination appearances; synchronization stores that identity. Cached siblings are removed only after matching Gmail identity and successful move verification, and the API reports removed cache IDs for single/bulk UI reconciliation. Regression fixtures cover Inbox/All Mail/custom-label deletion, default-folder collisions, equal-content distinct messages, and post-delete synchronization. Live read-only discovery confirmed the custom `Trash` versus `[Gmail]/Trash` collision and corrected roles; no live messages were moved during verification.
- Rapid mail processing: the browser queues provider actions, read updates, account sync and folder operations per account while optimistic deletion advances immediately. Mail revision conflicts return the current record; the browser retries once only for an unchanged remote identity/location, refreshes rollback records, and never retries uncertain provider writes. Unchanged synchronized downloads no longer increment revisions. Focused browser fixtures cover rapid unread deletion, synchronization races, changed-source rejection, bounded retries, independent-account read progress, bulk/partial failures and consecutive deletions of Gmail cache siblings. Backend and HTTP checks cover unchanged-download revisions and the structured conflict response.
- Persistent bottom status bar and recent activity dialog with account/level filters, copy and clear. The owner-protected private activity store retains 500 entries outside content backups. Sanitized stage events and final results stream through opt-in NDJSON responses; normal API clients retain JSON. IMAP transport errors distinguish timeouts/disconnects, with longer bounded reads, one pre-write reconnect, and read-only Gmail move recovery after uncertain transport failure. Protocol commands, credentials and message content are excluded from activity events. Backend, HTTP and browser fixtures cover retention/privacy, auth/CSRF, streaming success/error, reconnect limits, read-only recovery and desktop/mobile layout. Live outage recovery remains unverified.
- Keyboard/screen-reader review in the user's normal browsers. Full Vim operators inside rich text/source editors are not provided yet.
- Larger data sets and large backup restoration. Initial browser import/restore is limited to 8 MB; stop access and copy the full folder for larger migrations.

## Deliberate first-version limits

No complete mailbox synchronization or deletion reconciliation, external calendar edits/invitations, CalDAV recurrence expansion, complete MIME support, MBOX, full DokuWiki/CommonMark compatibility, offline editing, or DOCX/ODT/XLSX/ODS conversion. Sync is a bounded recent snapshot. Embedded raster document images are supported; external images are omitted. See the [user guides](README.md) for current behavior and the [initial implementation plan](implementation-plan.md) for the planned phases.

- Large-message IMAP sync checks sizes in batches, retains up to 32 KB of selected headers above 1.4 MB, and continues downloading normal mail. Header-only copies carry an explicit reader notice and no fabricated original EML. Gmail moves and interrupted-move recovery verify its unique message ID without body downloads; generic IMAP retains byte-content move verification. Stopped activity entries include the safe API failure reason. Fixtures cover an 8.1 MB message followed by normal mail, body-free Gmail Trash, and streamed failure reasons. A read-only live Gmail sync refreshed 30 messages in 27.3 seconds and retained the 8.1 MB message as headers only; no live move was performed.

- Mail now indexes headers in resumable batches of 100, prioritizing uncached recent identifiers and filling older history on later batches. Active sync processes up to five batches per account; opened folders also continue bounded batches. Opening indexed mail downloads and caches its body, with a retry control for connection failures. Settings → Mail offers offline body downloading. Large bodies retain the 1.4 MB limit. Lists render 100 rows initially with progressive loading and full-cache header search. Scripted provider tests cover a 270-message arrival burst, continuation and UIDVALIDITY checks; browser tests cover body retry and list loading. Live-provider acceptance remains separate.
