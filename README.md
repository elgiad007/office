# Portable Office

A personal office suite for a folder on your own computer or a PHP shared-hosting account. Mail, calendar, tasks, contacts, documents, wiki and simple spreadsheets share one keyboard-oriented interface. This is an initial implementation, with the limitations below.

## Run on Windows

Extract **the Windows release ZIP** into a writable folder, then double-click **Start Office.bat**. It starts the bundled local server on `127.0.0.1:8765` and opens your browser. Releases with portable Apache use four PHP FastCGI workers; other releases use PHP's built-in development server. The console displays a one-time setup token. Create your owner password in the browser. Use **Stop Office.bat** before moving the folder or removing a USB drive. Save work before stopping it. No Windows service, Docker, database server or system PHP installation is needed.

The executable has companion DLLs/extensions; keep the `runtime/windows/` files together. The bundle includes Mozilla CA certificates distributed by curl for verified TLS connections. Windows x64 is targeted. A missing Microsoft Visual C++ runtime can prevent PHP starting; see [runtime notes](runtime/windows/README.md). The development server is for localhost only, never public network hosting.

Optional: `Start Office.bat -Port 8766` or `Start Office.bat -NoBrowser`. Starting again reuses this folder's recorded process. It does not deliberately stop or reuse another application's server. The folder must be writable; Program Files is not a suitable default location.

Source checkouts do not contain PHP binaries. Build the Windows release with the packaging instructions below. For development, an existing PHP installation can run `php -S 127.0.0.1:8765 -t public`.

For concurrent local requests, use the [portable Apache development setup](docs/development-server.md). It uses the existing Windows PHP runtime with four FastCGI workers, requires no Windows service or WSL, and is selected automatically by Start Office when installed.

## Run locally on Linux

With PHP 8.2+ and PDO SQLite already available, run `sh start-local.sh`. Visit `http://127.0.0.1:8765`. After the first visit, retrieve the one-time token from `data/setup-token.txt` and complete setup. The same code and database format are used locally and on hosting.

## Install through cPanel

1. Upload/extract the hosting ZIP into a folder such as `/home/your-account/office`.
2. Set the domain/subdomain's **document root to `/home/your-account/office/public`**. The application parent and `data/` must not be publicly served. If your account cannot choose this root, resolve that with the host before deployment; do not copy everything into `public_html`.
3. Select PHP 8.2+ with PDO SQLite. OpenSSL is needed for account credentials; cURL and DOM are needed for HTTPS/CalDAV connectors. The owner must have write access to `data/`; do not use world-writable permissions.
4. Enable HTTPS using the hosting panel. Open the domain, read `data/setup-token.txt` in File Manager, and complete owner setup with a password of at least 12 characters. The token disappears after setup.

No Composer, Node, root access, Apache installation, cron job or persistent worker is required on the host. The parent `.htaccess` denies requests if the wrong root is selected; `public/.htaccess` permits the intended root. The root configuration is Apache-compatible; other web servers must likewise expose only `public/`.

Shared-host filesystem locking, outbound connections, PHP extensions and request limits must be confirmed on your actual account. This repository has not been deployed to hosting.com. Keep SQLite on a local filesystem with working locks, not a network-mounted folder.

Elapsed time appears in parentheses beside timestamps by default, using “now” for less than a minute, then minutes, hours or days (for example, `Nov 4, 10:30 AM (5 minutes ago)`). Disable **Show elapsed time beside dates** in **Settings → Look & feel**. Labels refresh once per minute while the page is visible; original dates remain available.

## What works in this version

- One-owner login, token-protected setup, CSRF-protected writes, idle session expiry, local encrypted provider credentials.
- Tasks with labeled status, priority and due-date badges. Task List view offers status/priority/due filters, due-date/status/priority grouping with collapsible groups, and due-date/priority/title/updated sorting. Defaults show unfinished tasks by earliest due date (overdue first, undated last), with no grouping. View preferences are saved; completing a task advances selection when it leaves the current filter. Priorities use High/Normal/Low, preserving existing custom values. Contacts include email, phone, company and group.
- Calendar Month, Week, Day and Agenda views with source visibility controls, local event editing and ICS import/export. Select a date or time slot to create an event. Timed input uses local time and is stored as an absolute timestamp; all-day dates and exclusive end dates remain date-only through editing and export. Views show cached events, including connected calendars as read-only copies.
- Basic word processing: headings, lists, bold/italic, tables, links, embedded images (PNG/JPEG/GIF/WebP under 900 KB), undo/redo, safe HTML and text import, HTML export, browser print/PDF. HTML is sanitized before displaying or editing; external/unsupported images are replaced by their alt text rather than fetched.
- Wiki: namespace-style page names, Markdown subset, `[[namespace:page]]` links, backlinks, source/preview and revision history. Supported Markdown includes headings, paragraphs, simple bullets, bold, inline/fenced code, HTTP/mailto links and blockquotes. This is not DokuWiki plugin/syntax compatibility or a complete CommonMark implementation.
- Workbooks with multiple sheets; visible grid A1:L30, imported data retained through Z100; arithmetic and SUM/AVERAGE/MIN/MAX/COUNT, references and ranges, cycle/error detection. CSV import/export and JSON export for full workbooks. CSV exports preserve formula source; JSON retains every sheet. Cross-sheet references and Excel file formats are unsupported.
- EML import/export with original source; HTML and plain-text message reading and local drafts. Use the HTML / Text only buttons above a received message, or choose a default under Settings → Mail. Dark mode adapts sender text, link and background colors for readability; use Original colors above the message to restore its light presentation for that message during this session. Outlook blank paragraph spacing is preserved. HTML uses an isolated frame with scripts and forms disabled; external HTTPS images require Load images for each message and may report that the message was opened. Embedded PNG/JPEG/GIF/WebP images up to 500 KB each are supported. The PHP DOM extension is required for HTML viewing. Text only uses the plain-text body when available or readable text extracted from HTML, including for nested multipart messages. Transfer encodings and character sets are decoded; scripts, styles and attachment contents are excluded from the text view. Previously cached multipart messages are read from their saved originals automatically. Original EML import/download is initially limited to 1.4 MB per message; larger Gmail API messages initially retain headers and metadata. IMAP checks message sizes first and retains only bounded headers and metadata above 1.4 MB, without aborting the remaining downloads. For larger messages, Download message body retrieves text parts separately and Show attachments retrieves file metadata. Individual files download on demand. No original EML is offered for a partial copy. Gmail IMAP read/move/Trash operations remain available using its account-wide message identifier. File attachments support individual downloads, image/PDF previews, Save all as ZIP, and on-demand IMAP/Gmail retrieval. Encrypted messages and complete MIME support remain deferred. Parsing is bounded to 20 nested levels and 500 parts.
- Google OAuth authorization/refresh, Gmail Inbox/Archive/Trash synchronization, Google primary-calendar agenda download, Gmail send/read/archive/trash/restore; TLS IMAP Inbox/Archive/Trash synchronization, verified folder moves, read operations and SMTP send; read-only CalDAV collection download. **These connectors are implemented but not accepted against real accounts yet.**
- Light/dark/system appearance, accent palettes, compact density, configurable home-row commands, responsive layout and standard focus navigation.
- Logical JSON backup of content, cached messages, preferences and revisions; transactional restore into an empty workspace. Credentials, owner password, OAuth tokens and local process state are excluded. Restored provider data becomes a local archive.

## Account connections and active-use sync

Choose **Settings → Add account**, then select either:

- **Account setup:** Gmail offers an app-password option without Google integration setup, or Google sign-in after one-time installation configuration in Settings → Google integration with optional read-only Calendar access. IMAP and CalDAV offer guided and manual setup, optional checks, and a masked review before saving.
- **Manual setup:** all configuration fields on one screen, with the same validation and optional checks.

Switching between these paths, going Back, or temporarily choosing another provider preserves entered values while the dialog remains open. Each provider has a separate draft. Secrets stay masked in inputs and are omitted from the review. Drafts are kept only in memory, never localStorage; closing the dialog clears them. Saving stores credentials encrypted on disk. Neither path automatically synchronizes or sends mail.

**Test connection** signs in to IMAP using read-only Inbox access, checks MOVE support and the archive folder, and signs in to SMTP without sending a message, or checks a CalDAV collection's properties without downloading events. Archive checks list folders and read their status; they do not move messages or prove write permission. Results are cleared if settings change. Checks do not save an account or validate mail delivery. You may save for later if a check cannot run on the current host. Google accounts are created only after Google authorization succeeds and Gmail confirms the account address. Cancelled or failed authorization does not create an account.

All connections require public DNS hostnames and verified TLS; private LAN endpoints and self-signed certificates are intentionally not supported initially. Generic mail currently uses **IMAP 993 and SMTP 465 with the same username/password**. STARTTLS/587, separate SMTP credentials are future work. Check your provider's app-password policy.

For CalDAV, supply the actual calendar **collection URL**, username and password/app password. Discovery from a service's home URL is not implemented. Redirects are not followed; use the final HTTPS endpoint. Only ports 443/8443 are accepted.

For email without Google Cloud setup, choose **Add account → Guided setup (or Manual setup) → Gmail — app password**. Enter a label, your full Gmail or Google Workspace address, and a Google app password. Enable 2-Step Verification in Google, then create a password at [Google App passwords](https://myaccount.google.com/apppasswords). Use the 16-letter app password rather than your normal account password; spaces between groups are removed. Some managed accounts, security-key-only verification, and Advanced Protection do not offer app passwords. This option connects email only. Office supplies `imap.gmail.com` on TLS 993 and `smtp.gmail.com` on TLS 465, uses your email as the username, detects the server-designated All Mail and Trash folders, and encrypts the password. **Test connection** checks Inbox, archive/MOVE support, Trash access, and SMTP login without sending or moving mail. Gmail's All Mail includes Inbox and sent mail, so the IMAP Archive view can overlap Inbox. Real-account archive/trash behavior still requires verification.

For Google sign-in and optional Calendar access, in **Settings → Google integration**, configure your own Google Cloud web OAuth client once per installation. Enable Gmail API and optionally Calendar API. Register the **exact callback URL** shown there, including `api.php?r=oauth-callback`. Configure the consent screen and test users as needed. Save the client ID, secret, and callback. A blank secret retains the saved secret only for the same client ID. These settings are encrypted and excluded from JSON backups.

You can register both your hosted HTTPS callback and your local callback in the same web client. The Windows launcher defaults to `http://127.0.0.1:8765/api.php?r=oauth-callback`; use the address actually shown by your installation. Keep its hostname and port fixed. Enter the client credentials once in each installation and authorize accounts separately there. Do not copy a live database to transfer connections.

Then choose **Add account → Guided setup (or Manual setup) → Gmail**, enter your email, optionally include Google Calendar, and choose **Connect with Google**. Google confirms the actual address; duplicate accounts are rejected. Reauthorization must use the original address. Gmail modify access includes reading, sending and organizing messages; Calendar access is optional and read-only. Existing Google accounts keep their credentials and Calendar behavior. Changing integration credentials affects future connections; existing connections continue using the credentials under which they were authorized.

Personal-use verification exceptions and testing-token expiration depend on Google's policy; an unverified/testing client is not promised permanent authorization. Testing grants normally expire after seven days. Domain/port changes require updating the registered callback; existing accounts retain their original callback for reauthorization.

Opening the app initiates a check. Further checks run every two minutes while the tab is visible and the owner has interacted within the last two minutes. Manual **Sync now** also checks accounts. Hidden or idle tabs initiate no new checks; an already-running request may finish. No jobs or sends happen when the application is closed. No push notifications or reminders are delivered while it is closed.

Mail synchronization checks complete identifier lists for **Inbox, Archive and Trash**, indexing message headers in resumable batches of 100 per folder and refreshing previously cached membership and read flags. New arrivals are prioritized; subsequent batches fill older history without a fixed message-count ceiling. Each active check processes up to five batches per account, then continues at the next check. Accounts take turns between batches so older history does not delay other accounts' first checks. Gmail lists are paginated; IMAP uses folder-specific UIDs and UIDVALIDITY. Downloads remain limited to 1.4 MB per message. Gmail Archive means mail without Inbox, Trash, Spam or Draft labels, including sent messages outside Inbox; custom labels are preserved. Calendar downloads remain limited to up to 100 objects in the previous week/next 90 days.

IMAP header downloads combine headers, flags and message sizes in requests of up to 25 messages. Cached flags use compact UID ranges in bounded batches; servers advertising CONDSTORE skip unchanged cached flags and return only changed flags otherwise. Validated new Inbox headers become visible during a streamed sync, before Archive and Trash finish. If later work fails, these headers remain cached, while absent-message recovery and move reconciliation wait for a successful complete scan. After an account's first 100-message pass, its remaining four header windows share one connection and folder scan, subject to the existing time budget. Offline body downloads and repairs still preflight message sizes. Activity records cache preparation/publication times and the elapsed time until new Inbox headers are ready; it excludes message contents and credentials.

In Mail, accounts and their nested folder lists appear directly beneath **Mail** in the left application panel. Expand an account there and choose **Refresh folders** to discover its server folders or Gmail labels. The list is saved for later use, including offline browsing of downloaded messages. On narrow screens, use the **Show mail folders** button beneath the Mail icon to open the folder panel; selecting a folder closes it. Nested folders have expandable parent groups. Folders with identical names in different accounts stay separate. Select a folder to refresh its contents independently of other folders. **Load next batch** indexes another 100 message headers; previously cached messages remain available. Opening or refreshing a folder processes up to five batches, with remaining history continued by later refreshes. The currently open account folder is also refreshed during the normal active-use sync checks and **Sync now**. Other custom folders refresh when opened or through **Refresh mail**. Folder lists refresh on request. Message bodies download when opened and stay cached. Settings → Mail → **Download message contents during sync for offline use** also downloads bodies during later sync batches, including previously indexed headers. Bodies over 1.4 MB retain the existing provider-reader notice. Message lists initially render 100 rows; **Show next 100 messages** reveals additional cached rows, while header search covers the full cache. Body text search covers downloaded bodies. The cache fills progressively; failed network requests leave downloaded mail available.

Choose **New folder** (or **New label** for Gmail) to create one. Enter the full path for nested folders, using the server's hierarchy separator (commonly `/` or `.`); Gmail uses `/`. Select a custom folder to rename or delete it. IMAP renames update cached paths, including subfolders. IMAP deletion requires an empty folder without subfolders, checks the server again, and asks for confirmation. Stale cached originals are retained in Recovery copies. System folders and parents containing system folders are protected. Gmail deletion removes a label from messages without deleting the messages; renaming changes the selected label only. International IMAP folder names use modified UTF-7 and require PHP iconv.

Open a connected message and choose **Move / Labels** to file it. Use the selection shortcut (`v` by default) on several messages to file them together; all selected messages must belong to the same account. IMAP moves use the same verified MOVE operation as Archive. Gmail offers **Add label**, **Remove label**, or **Move here**. Move here adds the chosen label and removes Inbox/Trash; other labels remain. One cached Gmail message can appear in several label views. Bulk operations run message by message; if one fails, Office reports how many completed and reloads the cache. Refresh the affected folders before retrying an uncertain provider operation.

Synchronization publishes an account's mail changes only after all selected folder scans and requested downloads succeed. A refused folder, incomplete search, failed page or time-budget error keeps the previous mail view. Large accounts or slow servers can exceed the 45-second mail budget; Office reports this rather than treating a partial list as deletions. Changes made on another device appear on the next successful sync. Folder changes during a scan can require another sync.

Messages missing from the synchronized folders leave the normal mail view. By default Office keeps their originals under **Recovery copies**, separate from **All cached mail**. Such a message may have been deleted or moved to an untracked folder; recovery does not establish its current location. Choose **Save locally** to retain an independent copy in **Local mail**, or **Discard copy** to remove only Office's recovery copy. Settings lets you disable retained recovery copies; absent cached messages are then removed during the next successful sync. Local mail is always independent of server reconciliation. Earlier **Not in Inbox** entries appear in Recovery copies and are reconciled on the next sync.

Choose **Settings → Connected accounts → Repair / resync** for an IMAP or Google account to rebuild membership and refresh the contents of previously cached messages as well as recent downloads. Repair keeps credentials and local mail; it requires a working server connection. Connection and permission failures appear in the account status and the action's error message. This does not recover a message permanently deleted from the server unless a local recovery copy exists.

Mail actions update the provider: **Archive**, **Move to Trash**, **Restore to Inbox**, **Move / Labels**, and read/unread. Trash is a server folder, so provider retention policies apply; Office does not permanently expunge server mail. IMAP moves require UID MOVE support and existing folders. Defaults `Archive` and `Trash` resolve unique server-designated folders or unique nested folders with those names. Explicit custom paths must match exactly. Missing default folders are skipped during sync; moving mail there reports a missing-folder error. Ambiguous or missing explicitly configured paths fail the scan. Office creates folders only through the explicit New folder action and never uses a broad EXPUNGE fallback. IMAP over Gmail may require an explicit existing archive path; the Google connector handles Gmail's labels directly.

An IMAP move succeeds only after Office verifies that the source UID existed, disappeared from its source folder, and the same message contents appeared under a new UID in the destination. The cache then stores the destination folder, UIDVALIDITY and UID, allowing subsequent read, trash and restore actions. Verification examines at most 10 new destination messages. If confirmation fails after MOVE, use Sync now or Repair / resync before retrying; the move may already have completed. External moves are matched only when the downloaded message contents are identical and unambiguous; Message-ID searches also check older destination messages outside the recent window. Otherwise the old copy is kept separately according to the recovery preference. Sync, repair and mail actions on the same account cannot overlap. The **Cached** badge describes a downloaded copy, not a live connection. **All cached mail** excludes Trash and recovery copies; use their dedicated folder filters to manage them.

Sending requires an explicit button and confirmation. A draft is marked as sending **before** contacting the provider. Failed/interrupted sends remain “Delivery uncertain”; check the provider/recipient before composing a replacement. There are no automatic resend attempts. Generic SMTP does not append a Sent copy to IMAP. The app itself retains a local Sent record. Reply composition quotes the original text and omits its attachments. Forward creates a draft including the original files. Threading headers, multiple recipients, CC/BCC and signatures remain deferred.

Attachments appear above received message content, with filename, type, size and offline availability. Choose Show attachments for header-only mail. Preview supports PNG/JPEG/GIF/WebP and PDF in an isolated browser frame; other files download for opening in their usual apps. Save all downloads a ZIP and gives duplicate filenames unique names. Drafts accept Add files or drag and drop, retain files across reloads, and allow removal before sending. Limits: 10 MB per file, 20 MB total per draft or Save all, and 100 files per draft. These limits apply to decoded bytes; IMAP metadata reports encoded sizes until downloaded. Files are stored separately in SQLite, included in full backups, retained in Sent and local recovery copies, and removed with their message. Only downloaded files remain usable without the provider. Restore cannot recover files that were never downloaded.

Large-message text retrieval is limited to 1.4 MB of text parts; it does not reconstruct the original EML or fetch all inline images. Attachments can still download separately. Signed/encrypted MIME, cloud attachment links, attachment-content search, and launching desktop apps directly from the browser remain outside this workflow. For hosted installations, allow at least 16 MB JSON requests (128 MB for restoring larger backups), 256 MB PHP memory and suitable web-server request limits; the bundled PHP configuration supplies these settings.

Calendar imports retain raw event sources for original download when available. The calendar does not expand CalDAV/local recurring series or handle invitation replies, exceptions, alarms or remote writes. Google expanded instances are read from its API. Use your existing calendar client for those workflows. Local task recurrence/contact synchronization are also deferred.

Wiki pages open in Read view. Press the insert-mode shortcut (`i` by default) or choose **Edit source** to edit Markdown; choose **View page** to return to the rendered page. New pages open in insert mode.

New items open as unsaved drafts held only in memory. Choose **Save** (or Ctrl/Cmd+S, or `s` in normal mode) to create the first saved copy; edits then auto-save. **Discard Draft** removes an unsaved draft without storing it. Leaving an unsaved draft offers **Save**, **Discard Draft**, and **Cancel**. Refreshing or closing the tab warns about unsaved work. Preview, export, and sync never perform the first save. Save a mail draft before sending or adding attachments. Saved mail drafts also use **Discard Draft**; other saved items use **Delete**. Sending or discarding an email draft returns to its previous mail folder, including account-specific folders, with its search restored. Saving a draft keeps the composer open.

## Keyboard operation

Normal-mode item shortcuts work in both the list and nonediting content and keep focus in the active pane. `Ctrl+f` / `Ctrl+b` scroll the focused list or content pane down/up one page with overlap; `Ctrl+d` / `Ctrl+u` scroll half a pane down/up. These work in HTML mail, support key repeat, and leave typing fields and editors with their native shortcuts. Plain `d` / `u` also scroll half a pane down/up, matching Vimium. Capital `D` deletes, capital `U` undoes mail deletion, and `x` completes tasks. Saved former default delete/undo bindings are upgraded to `D` / `U`; other custom mappings are retained. In a focused read-only mail body (plain text or HTML), configured down/up keys (`j/k` by default) scroll, and `gg/G` go to the top/bottom; `n/N` navigate messages while keeping content focus. List rows, mail headers and toolbars, drafts, and other apps retain item navigation. Deleting or moving the current item advances to the next visible item, falls back to the previous item at the end, and clears the detail when no items remain.

In Mail, `U` undoes the last deletion gesture, including a selected batch. It waits for pending deletions and restores only confirmed successes. Local messages retain their original ID, full content, attachments and revision history; connected messages return to their original server folder or Gmail memberships. This is separate from Restore to Inbox. The binding is remappable in Settings and applies outside editors and dialogs. Undo is available in the current page for fifteen minutes; reloading clears the shortcut's history. The server retains up to 100 receipts and 64 MB of undo data, and refuses further undoable deletions when full. Failed or uncertain provider operations require checking and synchronizing the mailbox before another action; undo never automatically repeats an uncertain provider write.

Right-click an item in any application's list or its nonediting content to open its action menu. Ctrl/Cmd-click toggles individual items; Shift-click selects a range. Right-clicking within a selection keeps that selection, while right-clicking another item targets that item alone. Menus show actions available for the entire selection, including bulk task completion, mail actions, export, and local deletion. Local deletion and discarding recovery copies require confirmation. Bulk changes run one item at a time; a failure reports how many completed and refreshes the view before retrying.

With the list or nonediting content focused, Shift+F10 or the Menu key opens the same menu. Use arrows, Home/End and Enter to choose an action, or Escape to close it. Text fields and editors retain their normal browser context menus.

Press `?` (or your remapped help key) for full-screen keyboard and command help. Search immediately filters shortcuts, actions, contexts and parameters, with a result count and Clear search button. Escape closes help and restores focus. The reference uses current key bindings and the shared command registry. Normal mode: `j/k` next/previous, `h/l` focus list/detail, `gg/G` first/last, `/` search, `n/N` move through results, `g 1`–`g 7` change apps, `c` create, `i` edit, `v` select, `s` save, `D` delete the current item (with confirmation) or move connected mail to Trash. Mail: `a` archive selected messages, `m` Quick Move to a folder, `r` reply. `Escape` leaves edit mode and saves changes only to existing items; Ctrl/Cmd+S saves, including the first save of a new draft. Single-character bindings can be remapped in Settings. The delete shortcut leaves synced read-only items and connected mail already in Trash unchanged. Ctrl+Enter sends the current draft, with confirmation enabled by default.

Quick Move works like eM Client: press `m`, type a folder name, use ↑/↓ to choose a match, then Enter to move or Escape to cancel. Matches include folders from all connected mail accounts, with account names to distinguish duplicates. It moves selected messages, or the current message when none are selected. Read/unread remains available through buttons and menus. Cross-account moves copy the full original, verify the destination contents, then move the source to its account's Trash. Transfers use the existing 1.4 MB original-message limit and require UIDPLUS on IMAP destinations. Failed verification keeps the source; uncertain copies cannot be retried automatically, preventing duplicates. Check the destination manually if that occurs. Live cross-account provider acceptance remains unverified.

In spreadsheets, focus a cell, use arrows to move, i/Enter to edit its formula, Escape to return, Tab/Shift+Tab to move cells. Typing fields keep their normal text input and browser editing behavior. **Full Vim motions/operators in text editors are not implemented yet.** The current mode distinction supplies home-row application navigation, not a full Vim emulator.

The Mail list count is labelled **cached messages**: it counts messages stored in Office for the current folder or search. It can grow as older messages download, without indicating new arrivals. During sync, the top status shows each active account and batch number. The bottom bar shows the current folder, message progress within the batch, and messages still to cache. Low-level connection details remain in View activity. When a check reaches its batch limit, **Older mail remains · continues on next check** explains that more history is pending.

## Connections between items

Opening a connected email selects and scrolls to its row in its latest cached folder, expanding its date or sender group when needed. Custom IMAP folders and Gmail labels open in their account view when available. Trash and recovery copies keep their restore/save/discard actions; the delete shortcut explains those options. If the linked message is no longer available, Office reports that instead of selecting another message.

All seven item types can be connected to each other. Connections appear on both items and stay intact when titles change. They are Office data, including for read-only synced mail and events; linking does not edit provider content.

Select an item and use command mode:

- `:link event budget review` searches events by title or cached description; `:link budget` searches across types. An exact record ID also works.
- As you type, use Up/Down to choose a match, Tab to fill its exact ID, and Enter to create the connection. Escape dismisses suggestions while retaining command mode and the typed text. Escape with suggestions closed exits command mode. Ambiguous searches require selecting an exact item.
- `:new linked mail`, `:new linked event`, or any other creation type opens a linked draft. Its first save creates the item and connection together. Discarding leaves no connection. An unsaved source must first be saved through the normal Save/Discard/Cancel flow; discarding the source cancels linked creation.
- `:unlink [type] <name or ID>` searches only existing connections and removes the chosen connection. It does not delete either item.
- `:links` opens the current item's connection list and graph. `:links all`, or **Connections** in the sidebar, opens the workspace view. Search filters by either endpoint's title. Graph nodes can be focused with a click or Enter/Space; open an item from the list. Lists load 100 edges per page, with **Load more connections**; the graph shows up to 80 items from the loaded connections.

Every item's header shows a compact **Connections · count** label and **+ Link** action. Select the count to open a popover with linked items, unlink actions, and **View map**. The list floats over the content instead of occupying space below it. Escape closes the popover and returns focus to the count; arrow keys move through its actions. Unsaved drafts show disabled controls until saved. Opening a connection switches apps and reveals the target outside the current search, mail folder, or hidden calendar. Mail searches cover locally cached descriptions, not bodies that have never downloaded. Existing Markdown `[[wiki links]]` and their title-based backlinks continue to work separately.

Full backups include connections; older backups without them remain supported. Deleting a connected item offers **View connections**, cancellation, and a per-item choice to preserve or remove its links. Preservation is selected by default and replaces the source with a named, editable connection hub in **Documents**, containing only a deletion note and the relationships, without the original body, metadata, or attachments. Bulk deletion allows a separate choice and hub name for each connected source. Moving provider mail to Trash keeps its connections on the message. Discarding a recovery copy offers the same hub option as deleting local items. Mail deletion undo restores links and removes an untouched replacement hub; an edited hub stays linked to the restored message. Verified mail moves, duplicate reconciliation, cross-account transfers and recovery-to-local conversion preserve connections. An external move whose identity cannot be verified cannot safely retarget them.

Connection storage references generic record IDs with no per-type columns. Frontend type labels, creation commands, and distinguishing fields live in `frontend/item-types.ts`; future applications register their type there, add their normal application/navigation behavior and backend validation, and reuse the same connection APIs and schema.

## Moving and backing up

Use Settings → Download full backup for a consistent snapshot. Backups include message/document contents and are sensitive; store them privately. Restore into a fresh empty installation so existing records cannot be overwritten accidentally. Browser file imports, including JSON backup restore, are initially limited to 8 MB; for larger workspaces, stop access and copy the complete folder. Chunked/streaming large-backup restore is future work. Reconnect provider accounts after restoring.

Alternatively stop the local server (or put hosted access into maintenance) and copy the **whole application folder**, including its private data and key. The key and encrypted credentials travel together; this is protection against exposing the database alone, not disk encryption. Sessions should not be shared between people. Browser sessions/callback registrations do not become portable merely by copying files. Never move/copy just an active SQLite database file.

## Development and packaging

The frontend source is TypeScript in `frontend/`. Browser-ready ES modules in `public/` are generated and committed so a checkout or release ZIP runs directly with PHP. Edit the TypeScript source, not the generated JavaScript. The PHP backend, database format and hosting requirements are unchanged; Node and pnpm are development tools only.

Install development dependencies using Node.js and pnpm, then build and check the frontend:

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm typecheck
pnpm test
```

`pnpm build` compiles TypeScript without bundling or a framework. `pnpm build:check` checks types and verifies that the committed JavaScript matches the source. Packaging and the Windows browser test runner perform that same check and stop if the output is stale. Commit updated `public/*.js` alongside frontend changes. To rebuild automatically while editing, use `pnpm exec tsc --watch`, then run `pnpm build` before committing to restore the generated-file headers.

Shared contracts for records, accounts, preferences and route-specific API responses live in `frontend/types.ts`. Types are checked during development; PHP still validates requests and imported data at runtime. Type checking does not replace provider or browser acceptance tests.

See [the implementation plan](docs/implementation-plan.md) for staged work and acceptance criteria. No real-account or shared-host compatibility is implied by local tests.

Gmail IMAP uses the server-designated Trash and All Mail folders for the default Trash/Archive actions, even when custom labels named `Trash` or `Archive` also exist. Moves reopen the source to verify removal and locate the destination through Gmail's account-wide message ID. Proven cached appearances of the moved message are reconciled together; unrelated messages with identical content are kept. After upgrading from the earlier app-password connector, refresh Office, choose **Refresh folders** for the Gmail account and use **Repair / resync** to refresh previously cached locations. An earlier custom `Trash` label is retained; messages filed there can be selected and moved to the actual Trash using the mail action. Live Gmail deletion acceptance remains separate from fixture checks.

Rapid mail actions keep the list responsive while provider operations are queued separately for each account, including automatic read updates and synchronization. Unchanged downloads keep their current revision. If an action is rejected before any provider write because its cached revision changed, Office refreshes the copy and retries once only when the account, source message and location still match. Changed sources and uncertain provider failures are not retried automatically. Failed deletions restore the latest cached copy, and multiple queued deletions of proven Gmail appearances share the confirmed Trash result.

The bottom status bar shows current and queued work with a slow accent band sweeping left to right. The sweep stops when work ends; after a brief quiet interval the status becomes Ready. Routine log polling does not count as activity. Reduced-motion preferences replace the sweep with a steady highlight. **View activity** opens the latest 500 events with timestamps, account labels, operation stages, elapsed times and errors; filter by account or level, **Copy visible log**, or **Clear log**. The private `data/activity.sqlite` store survives refreshes and is excluded from content backups. Logs contain summaries, not passwords, OAuth tokens, message contents or raw protocol commands. Sign-in and CSRF protection apply to activity access and clearing. IMAP progress is streamed during requests where hosting allows streaming; retained history is also refreshed periodically.

IMAP waits up to 20 seconds for a read (previously 8), with a 10-second connection timeout and a bounded request recovery window. Errors distinguish interrupted/closed connections from timeouts and identify the failing stage. Broken pre-write connections can reconnect once. If a Gmail move is interrupted after being sent, Office opens a fresh connection and checks the unique message in the source and destination; a verified destination updates the cache without sending another move. An unresolved result reports uncertainty and requires sync before retrying. Generic IMAP moves and other writes are not blindly repeated. Local fixtures cover recovery; a live outage during Gmail deletion has not been induced.

### Mail list appearance

Settings → List appearance configures the left and right fields and text sizes on each of three lines, with a live preview, sender name/email options, and Reset to default. The default shows sender and sent date, then a smaller subject and attachment icon, then the first nonempty body line. Long text ends with an ellipsis. Settings persist and are included in backups. Header-only messages show an unavailable preview until their body downloads; ? means attachment status is unknown. Inline message images do not count as attachments.

## Commands

In normal mode, `:` opens the status-bar command line. Enter executes once; Escape cancels and returns focus. `:head` shows the selected mail message’s headers. `:q` saves pending edits and signs out to the password screen. `:log`, `:errors`, and `:warnings` open View activity with All levels, Errors, or Warnings selected. `:new` creates an item in the current application; `:new mail|event|task|contact|doc|page|sheet` switches application and creates one item. In Settings, specify the item type. Commands are unavailable while typing in editors, search, dialogs, or the login screen.

Navigate without creating an item using `:mail` (`:m`), `:calendar` (`:cal`), `:tasks` (`:t`), `:contacts` (`:con`), `:docs` (`:doc`, `:d`), `:sheets` (`:sh`), `:wiki` (`:w`), or `:settings` (`:set`). These commands save pending edits and wait for attachments before switching. They accept no arguments; aliases require an exact match. Help lists aliases alongside each canonical command and includes them in search.
